Source and artifact mapping
- capacitor.config.json and ios/App/App/capacitor.config.json both set server.iosScheme to https. The native wrapper therefore loads https://localhost. It does not load capacitor://.
- app.js setupInstallableApp registers ./service-worker.js only when navigator.serviceWorker exists and location.protocol is http: or https:. https: does register. capacitor: and file: do not. A missing serviceWorker does not register. The comment that says the worker is unused inside the iOS wrapper is stale: the https scheme makes the gate true on device.
- Revision 2 and revision 4 service-worker.js are the same file in source, www, and ios/App/App/public. SHA-256 e0f4d0ad85a743be36a5f37056a5f0575905f25ce3aefa884d00d720a957e051. Cache name boriken-genetics-logbook-app-v81.

- Revision 4 changed build57.js (now ec8ffb75ae9c4aedcb026ae57a418300b83ee973277d1ebe48c2b66a24d6c5b3) and build63.css (now d0ba0dd2683df87603248bce9317197e2afb98d770dc69ac405e6891203b03ed) without changing the worker script. The update check installs a new worker only when service-worker.js bytes change. Until that happens, the fetch handler is cache-first: caches.match returns the stored response and does not read the new bundle file. Activate deletes other cache names only after a new worker installs. WKWebView Cache Storage lives in the app container, so an update of the same bundle id keeps the old v81 cache.
- That is why an unchanged v81 script can keep serving revision 2 build57.js and CSS after the revision 4 bundle is installed. It is not a guess about a second cache. The compiled revision 4 binary itself is unchanged by this patch.
