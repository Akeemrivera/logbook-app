Service worker proof
The revision 5 file scripts/b63-r5.test.js is a Node sandbox. It builds a fake cache and a fake fetch, then runs the worker script inside vm. That run is not a browser and not a device. Its pass remains a sandbox pass. This revision does not rewrite that file and does not treat it as browser proof.

scripts/b63-sw-browser.test.js launches the installed Chrome at /opt/google/chrome/chrome. It fails if that binary is absent. It does not substitute the sandbox. Over http://127.0.0.1 the page first registers a fixture worker whose cache name is boriken-genetics-logbook-app-v81 and whose cached build57.js body is the text REV2-STALE. Chrome served that stale body. The server then switched /service-worker.js to the real revision 5 worker, cache name boriken-genetics-logbook-app-v82, with cache:'reload' precache. Chrome installed that script, deleted the v81 cache, and served the current build57.js bytes (SHA-256 matched the file on disk). Network emulation was then set offline, and the same build57.js bytes were served from the v82 cache. Stdout SHA-256 is 37f82eed57f5fb021b467bfbcbc85895da126fb2cf8d6d72e0fdc59ae102af9b. This is desktop Chrome on this machine. It is not the iOS wrapper and not a device.
